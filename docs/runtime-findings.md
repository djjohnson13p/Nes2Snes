# CV3 runtime findings

Evidence: local `build/trace/trace-summary.json`, generated by `tools/trace_rom.py` and the FCEUmm probe. This is a bounded execution sample, not a statement about unvisited code.

## Identity and entry points

The uploaded file declares NES 2.0, mapper 5, submapper 0, NTSC timing, 256 KiB PRG and 128 KiB CHR, with no trainer or trailing bytes. SHA-256: `085ec6395681c7ebfda19c2986069c21a3d27738cc61ada76249de70a07ed7d3`.

In the final 8 KiB PRG bank mapped at `$E000`, the vectors are NMI `$E053`, RESET `$E00B`, IRQ `$E11A`. The capture observes these entry paths. Filename alone is not used to certify a release/region beyond what the actual header and execution establish.

## Observed mapper behavior

- `$5100 = $02`: 16 KiB `$8000-$BFFF` window plus 8 KiB `$C000-$DFFF` and `$E000-$FFFF` windows.
- `$5101 = $03`: 1 KiB CHR banking; separate sprite and background register sets receive writes.
- `$5104 = $00`: ExRAM used as nametable memory in this sample.
- `$5105` receives `$44`, `$55`, `$E4`, `$FF`. Mirroring cannot be treated as one fixed header flag.
- `$5115` receives `$00`, `$80`, `$82`, `$84`, `$88`, `$8A`, `$8E`, `$90`, `$94`, `$96`, `$98`, `$9A`, `$9C`; `$5116` receives `$87` and `$9E`.
- Scanline IRQ target `$5203` receives `$00`, `$08`, `$2E`; IRQ control `$5204` receives `$00` and `$80`.
- Observed code writes ExRAM at `$5C00-$5CBF` and `$5FC0-$5FCF`; ignoring ExRAM would break the covered paths.

These observations provide constraints for a port; they do not justify removing bank switching, IRQs or mapper-dependent rendering without a replacement.

## Audio correction

The earlier conversation inferred expansion-audio use from the presence of MMC5. That was not justified. This trace observes `$5010 = $00` and ordinary NES APU accesses; it does **not** observe writes to the MMC5 pulse-channel registers `$5000-$5007`. Mapper capabilities and a game's actual use of them must be distinguished. Unvisited code still needs coverage before making a whole-game claim.

## CPU compatibility constraints

A 65C816 is not a drop-in execution target merely because its opcode family overlaps. A native-mode port must explicitly manage accumulator/index widths, stack initialization, bank registers, interrupts, indirect-addressing differences and decimal-mode behavior. Preserve original arithmetic/overflow and frame scheduling until regression tests demonstrate safe changes.

No unofficial opcode was encountered at the observed instruction entry points. This does not rule out unofficial instructions in unvisited code.
